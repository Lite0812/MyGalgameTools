# 脚本字节码反汇编与汇编工具规范

## 目标
开发一套精确的脚本字节码处理工具，包含 **三个 Python 文件**，支持反汇编与重汇编，且满足 **零突变（逐字节还原）** 要求。

### 交互方式与核心体验
- **拖放即用**：将多个二进制脚本文件直接拖放到 `disassembler.py` 图标上，自动在同一目录生成 `asm.txt`；将 `asm.txt` 拖放到 `assembler.py` 图标上，自动生成重建后的二进制文件（默认扩展名 `.rebuild`）。
- **命令行兼容**：支持通过命令行参数指定输入、输出文件路径及文本编码。
- **语义化文本**：`asm.txt` 是纯语义视图，绝不出现原始十六进制转储；普通反斜杠按脚本文本保留，无法安全显示的特殊字节用 `{{XX:XX}}` 占位符表示，杜绝乱码。
- **编码可配**：反汇编与汇编均支持用户显式选择文本编码，确保多语言脚本字符准确呈现。

## 交付物清单
1. `opcodelist.py` – 操作码定义模块  
2. `disassembler.py` – 反汇编器，读取二进制脚本，生成 `asm.txt`  
3. `assembler.py` – 汇编器，读取 `asm.txt`，重建二进制脚本  
4. `asm.txt` – 反汇编生成的可读汇编代码文件（示例输出）

## 0. 前置 VM 分析与指令集建模（Pre-Disassembly VM Analysis）

在正式启动反汇编生命周期之前，必须对目标脚本所使用的虚拟机（VM）进行彻底逆向分析，产出 **VM 分析定义文档**（`vm_analysis.md`）。该文档是后续所有解析、重建工作的唯一真值源，其完备性直接决定整个工程的正确性。

### 0.1 VM 类型识别与指令解析逻辑
- 必须明确目标 VM 的体系结构（如基于堆栈/寄存器、哈佛/冯·诺依曼架构）、指令编码风格及典型执行范式。
- 须完整描述指令的解码流程：如何从字节流中切分操作码与操作数，如何处理大小端、对齐及定长/变长编码。

### 0.2 全量 Opcode 字典与长度表
定义所有有效操作码，并输出 **Opcode 长度与格式表**，包含以下字段：
- `opcode`：指令助记符或数值标识。
- `byte_pattern`：二进制识别特征（可含掩码）。
- `length`：最小指令长度（定长）或长度计算规则（变长）。
- `operand_schema`：操作数类型列表，如 `imm8`、`imm16`、`strref`、`rel_offset`、`reg` 等。
- `sub_opcode`：若指令包含子功能码，指明其位置（如某位段或紧随的操作码扩展字节）及所有合法子码的行为语义。
- `variants`：若同一主操作码根据不同的操作数格式表现出不同的语义，必须列出所有变体及其切换条件。

#### 变长 Opcode 与子 Opcode 处理规则
- 对于变长指令，必须明确界定指令边界的判定依据（如首个字节高 2 位表示附加长度、操作数数量由立即数指定等）。
- 子 opcode 必须全部枚举，不得遗漏。在主反汇编器实现中，必须根据子码路由至正确的指令解释器，禁止将子码作为无关数据丢弃。
- 当操作数类型或个数不同会改变指令行为时，必须用 `opcode_variant` 机制区分，确保文本提取与代码生成时可准确选择对应逻辑。

### 0.3 跳转指令的标签化策略
- 所有无条件跳转、条件跳转、调用及返回指令必须提取其解析后的目标地址，并在 asm.txt 中生成 **符号化标签**（如 `loc_00001200`）。
- 分析文档中应明确跳转偏移的计算基准（相对于指令起始、指令末尾或 PC 值）以及地址空间范围。
- 当变长字符串重写导致指令流长度变化时，必须通过标签重定位目标偏移，而不是硬编码绝对地址，以消除游戏执行异常。

### 0.4 未定义 Opcode 的发现与校正流程
在反汇编过程中，一旦遇到当前 `vm_analysis.md` 未记录的疑似操作码，必须执行以下排查步骤：
1. 回溯原始脚本所属的宿主可执行文件（exe/elf），查找是否包含该字节序列的直接处理逻辑；
2. 检查邻近指令的边界是否存在因错误解析长度而导致的连锁偏移（即前一条指令的长度可能被误判，导致当前“opcode”实为操作数的一部分）；
3. 将修正后的定义回写至 `vm_analysis.md`，重新执行全量反汇编，确保地址空间零歧义。

## 1. 操作码定义 (`opcode.py`)

该模块必须明确定义目标 VM 的完整指令集，作为反汇编与汇编的唯一依据。

### 1.1 必须包含的信息
- `opcode`：指令助记符（如 `MOV`, `JMP`, `CALL`）或数值标识。
- `bytecode`：指令对应的字节值或特征序列（可含掩码，用于识别）。
- `length`：指令总字节长度（定长）或长度计算规则（变长）。
- `operands`：操作数列表，每项定义 `type`（如 `imm8`、`imm16`、`rel_offset`、`reg`、`strref`）和宽度。
- `sub_opcode`：若指令内含子功能码，必须枚举所有子码及其含义（如某寄存器字段、扩展字节）。
- `variants`：若同一主操作码因操作数不同而变化，需列出所有变体及其识别条件。

### 1.2 格式要求
以 Python 数据结构（字典、列表、类）组织，确保易于被反汇编器和汇编器导入解析。

**示例结构：**
```python
OPCODES = {
    0x01: {
        "mnemonic": "LOAD",
        "length": 3,
        "operands": [{"type": "reg", "bits": 4}, {"type": "imm16"}],
        "sub_opcodes": {}  # 无子码
    },
    0x10: {
        "mnemonic": "CALL",
        "length": 5,
        "operands": [{"type": "sub_opcode", "bits": 8}, {"type": "rel_offset", "bits": 32}],
        "sub_opcodes": {
            0x00: "PRINT_TEXT",
            0x01: "PLAY_SOUND",
            0x02: "SET_FLAG"
        }
    },
    # ... 必须覆盖所有有效指令
}
```

## 2. 反汇编器 (`disassembler.py`)

### 2.1 输入与运行方式
- **拖放支持**：将二进制脚本文件拖放到 `disassembler.py` 图标上，自动以该文件作为输入，生成 `asm.txt` 于同一目录。
- **命令行**：`python disassembler.py <input_script> [-o <output_asm>] [--encoding <codec>]`
  - 若未指定输出文件，则在输入文件所在目录生成 `<input_basename>.asm.txt`。
  - `--encoding` 指定文本编码（如 `cp932`、`utf-8`），用于字符串数据的解码与呈现。若未指定，默认使用 `cp932`，并写入 asm 头部的 `.encoding`。
- 依赖 `opcode.py` 中的定义。

### 2.2 处理要求
1. **全量解析**：从文件头到尾逐字节解析，不留任何未识别空隙。遇到无法识别的操作码须报错退出，并输出冲突偏移。
2. **变长指令与子码处理**：严格按照 `opcode.py` 的长度规则切分指令，并根据子码生成对应助记符（如 `CALL.PRINT_TEXT`）。
3. **跳转标签化**：所有跳转/调用目标地址必须映射为符号标签（如 `LABEL_00001200`），并在指令中引用标签而非硬编码偏移。标签定义行单独输出。
4. **地址空间覆盖**：除指令流外的数据块（如字符串表、指针表）也必须以伪指令或数据定义的方式完整呈现在 `asm.txt` 中，确保汇编器能重建所有字节。

### 2.3 输出格式 (`asm.txt`) —— 语义化与抗乱码规范
- 必须为 **纯文本文件**，每行一条记录，字段之间可用空格或制表符分隔。
- **标签格式**：每个标签定义前**必须插入一个空行**（文件首个标签可例外），以提高可读性。格式为 `label_name:`，无需缩进。
- **字符串与数据表示**：
  - 字符串伪指令 `.string "..."` 中，双引号内文本必须是按选定编码可读的字符。普通反斜杠不是 asm 转义前缀，应按脚本文本直接保留；对于无法直接显示的控制字符或可能导致乱码的字节，必须使用 `{{XX:XX}}` 占位符，每个占位符代表一个字节，例如 `{{FF:01}}`、`{{00}}`。
  - 其他数据定义（如 `.byte`、`.word`）以十进制或 `0x` 十六进制数值列表给出，例如 `.byte 0x00, 0xFF, 0x01`。不得在这些定义中夹杂原始字节注释。
- **注释**：仅允许使用 `;` 开头的语义注释（如解释变量用途），**绝对禁止**在任何注释中写入原始十六进制字节序列（例如 `; 00 01 FF`）。语义化文件不保留二进制原貌转储。
- **示例片段**（注意空行与占位符用法）：

```
; 脚本入口，编码：cp932

loc_00000000:
    LOAD    R1, 0x1234
    CALL.PRINT_TEXT    loc_00001000

loc_00001000:
    .string "こんにちは{{00}}ワールド"   ; 字符串以00结尾

loc_00001010:
    .byte 0x01, 0x02
```

### 2.4 文本编码选择
反汇编器在读取字符串数据时，使用 `--encoding` 指定的编码将字节序列解码为文本。普通反斜杠字节（如 CP932 的 `0x5C`）直接输出为 `\`；对于解码失败的字节、控制字符（如 `0x00`、`0xFF`）以及 Unicode 私用区字符，同样输出占位符。私用区字符按原始编码字节成组输出，例如 CP932 的 `F0 41` 输出为 `{{F0:41}}`。  
若未指定编码，工具默认使用 `cp932`，并在 `asm.txt` 头部用 `.encoding "cp932"` 明确记录，以便汇编器复用。

## 3. 汇编器 (`assembler.py`)

### 3.1 输入与运行方式
- **拖放支持**：将 `asm.txt` 拖放到 `assembler.py` 图标上，自动读取并在同一目录生成重建后的二进制文件（文件名基于原 asm 文件，如 `original.rebuild`）。
- **命令行**：`python assembler.py <input_asm.txt> [-o <output_bin>] [--encoding <codec>]`
  - `--encoding` 指定将 `asm.txt` 中的字符串文本编码为字节时使用的字符集；未指定时优先读取 asm 头部 `.encoding`，若缺失则默认 `cp932`。
- 依赖 `opcode.py` 定义。

### 3.2 处理要求
1. **解析汇编文本**：正确识别标签、指令、伪指令及数据定义。忽略空行及注释。
2. **编码指令**：根据 `opcode.py` 将助记符和操作数转换回原始字节流，包括子码的还原。
3. **标签解析与重定位**：根据标签定义计算所有跳转偏移，填入指令对应字段（注意偏移基准）。
4. **字符串与占位符处理**：对于 `.string` 伪指令，将双引号内的文本按指定编码转换为字节序列；普通反斜杠按文本编码，不作为 `\xNN` 转义解析；遇到 `{{XX:XX}}` 或 `{{XX}}` 占位符时，直接解析为对应的原始字节（忽略编码边界），不得产生多余字符。例如 `"こん{{00}}"` 将编码后的日文字节与 `0x00` 拼接。
5. **逐字节重建**：所有数据块（字符串、对齐填充等）必须按原样生成，保证与原文件完全一致。
6. **错误处理**：若汇编代码含有非法指令、操作数越界或无法识别的占位符格式，必须报错中止。

### 3.3 输出
- 重建的二进制脚本文件，默认命名为 `<原输入basename>.rebuild`，可通过 `-o` 指定路径。

## 4. 零突变验证
必须执行以下流程验证工具完整性：
```bash
python disassembler.py sample.sc -o sample.asm.txt
python assembler.py sample.asm.txt -o sample.rebuild.sc
diff sample.sc sample.rebuild.sc   # 无任何差异
```
`sha256sum` 或 `md5sum` 必须一致。若存在差异，需修正 `opcode.py` 或两工具的解析逻辑，直至达成逐字节一致。

## 5. 额外约束
- **严禁使用正则表达式直接从二进制中抓取文本**，所有信息必须通过反汇编后的结构化方式提取。
- **asm.txt 严禁把 `\xNN` 当作十六进制字节转义或输出原始十六进制字节注释**，确保纯语义化、无乱码。脚本自身的反斜杠控制码直接保留；任何单字节的不可打印值必须用 `{{XX}}` 表示。
- 若目标脚本含加密/压缩层，反汇编器需先完成解密/解压（可在 `disassembler.py` 内部实现，或作为预处理步骤），最终 `asm.txt` 中呈现的是**已解密/已解压**的纯净字节流视图；汇编器负责在重建后重新应用加密/压缩，确保与原始加密二进制一致。具体加解密逻辑需在 `opcode.py` 或单独配置中说明。
- 反汇编与汇编均必须支持通过参数选择文本编码，以适应不同语言游戏脚本。编码信息应清晰地体现在 `asm.txt` 头部注释中。

## 6. 验收标准
- 提供的 `opcode.py` 包含目标游戏脚本的所有指令（可从样例文件中经 VM 逆向分析获得）。
- 运行反汇编器，对官方脚本生成 `asm.txt`，内容完整、格式正确：标签前有空行，无 `\x` 转义，所有特殊字节使用 `{{}}` 占位，字符串可读。
- 运行汇编器读取该 `asm.txt`，输出与原始脚本逐字节相同的文件，编码选项保持一致。
- 拖放操作可直接工作，无需额外配置。
- 目录结构干净，仅包含 `opcode.py`、`disassembler.py`、`assembler.py` 和说明文件。
