# `DID_MES_00_DAT` 与 `DID_PURI_PARA_DAT` 解析分析

## 1. 结论

本次分析对象是：

- `MC_ADD_unpacked/DID_MES_00_DAT`
- `MC_ADD_unpacked/DID_PURI_PARA_DAT`

两者都不是 VM 字节码文件：

- `DID_MES_00_DAT` 是魔数为 `MBT0` 的消息数据库，由字符串偏移表、分组表、分组名池和消息字符串池组成。
- `DID_PURI_PARA_DAT` 是魔数为 `SAM\0` 的参数数据库，由三个固定长度记录区组成。
- EXE 不会在这两个文件中逐字节取 Opcode，也没有脚本 PC、二进制跳转、调用、返回或子 Opcode。
- `MBT0` 消息中的 `#TYPE_H`、`#FADE_SET` 等内容属于 NUL 结尾的文本命令语言。EXE 在取得完整字符串后才解析命令名；命令 ID 不存储在 DAT 中。

因此，`CLAUDE.md` 中有关 Opcode、跳转标签和子 Opcode 的要求对这两个文件不适用。工具应实现结构化数据的反汇编和重建，而不是虚构一套二进制指令集。

## 3. DAT 资源读取链

### 3.1 资源定位

`sub_408550` 接收 `DID_MES_00_DAT` 或 `DID_PURI_PARA_DAT` 这样的资源 ID，调用 `sub_408370` 填充资源描述符。它负责定位封包条目，不解析资源内部格式。

### 3.2 数据读取

`sub_4079A0` 根据资源描述符取得宿主文件名、绝对偏移和长度，随后执行：

1. 以 `rb` 打开宿主文件；
2. `fseek` 到条目偏移；
3. 分配条目长度大小的内存；
4. 用一次 `fread` 读取完整条目；
5. 返回内存首地址。

加载器存在一个“条目内容指向外部文件名”的特殊分支，但这两个样本在返回后直接以 `MBT0`、`SAM\0` 结构使用。两个格式的初始化函数均未调用解密或解压函数。

相关证据：

- `export-for-ai/decompile/408550.c`
- `export-for-ai/decompile/4079A0.c`
- `export-for-ai/decompile/570BA0.c`
- `export-for-ai/decompile/5789E0.c`

## 4. VM 与 Opcode 适用性

| Opcode | 命名 | 长度/格式 | 精确定义 | 佐证 |
|---|---|---|---|---|
| 不适用 | 无二进制指令 | 不适用 | EXE 按固定头字段、表项宽度和相对偏移索引数据，不存在取指循环 | `sub_570BA0`、`sub_5789E0` |
| 不适用 | 无二进制跳转 | 不适用 | 文件内偏移只指向表或字符串，不改变执行控制流 | `sub_472E90`、`sub_56FE00` |
| 不适用 | 无子 Opcode | 不适用 | `SAM\0` 是固定记录；`MBT0` 命令是字符串解析后的 EXE 内部枚举 | `sub_567680` |

体系结构判定如下：

- VM 类型：无 VM，数据驱动型数据库。
- 指令边界：无。
- 操作数：无。
- 跳转目标和重定位：无控制流跳转；仅需重算文件内数据偏移。
- Code/Data 分区：全部为 Data。
- 对齐：`MBT0` 的消息字符串入口按 4 字节对齐；`SAM\0` 使用头部给出的固定区段偏移。

## 5. `DID_MES_00_DAT`：`MBT0` 消息数据库

### 5.1 文件头

| 偏移 | 类型 | 当前值 | 含义 |
|---:|---|---:|---|
| `0x00` | `char[4]` | `MBT0` | 格式标识 |
| `0x04` | `u32` | `418` | 分组数量 |
| `0x08` | `u32` | `7941` | 字符串偏移槽数量，包含索引 0 的空槽 |
| `0x0C` | `u32` | `0xB0D4` | 分组表偏移 |
| `0x10` | `u32[]` | - | 字符串相对偏移表起点 |

`sub_570BA0` 没有显式比较 `MBT0` 魔数，而是直接读取 `+0x04`、`+0x0C` 和 `+0x10`。这意味着 EXE 信任资源内容，损坏的计数或偏移可能导致越界访问。

### 5.2 完整布局

| 范围 | 大小 | 内容 |
|---|---:|---|
| `0x00000..0x0000F` | `0x10` | 文件头 |
| `0x00010..0x07C23` | `7941 * 4` | 有效字符串偏移槽 |
| `0x07C24..0x0B0D3` | `0x34B0` | 3372 个零 `u32` 填充槽 |
| `0x0B0D4..0x0C46B` | `418 * 12` | 分组表 |
| `0x0C46C..0x0D993` | `0x1528` | ASCII 分组名池 |
| `0x0D994..0x75147` | `0x677B4` | CP932 消息字符串池 |

样本中的填充区全部为零。分组名按表项顺序紧密排列；每条消息字符串连同 NUL 结束符独立补零至 4 字节边界。

### 5.3 字符串偏移表

每个表项都是文件相对 `u32` 偏移：

```text
字符串地址 = 文件基址 + 字符串偏移表[字符串索引]
```

- 索引 0 的偏移值为 0，作为空槽保留。
- 索引 1 至 7940 指向 NUL 结尾字符串。
- 每个有效偏移都落在 `0xD994..EOF`。
- 当前样本的 7940 条字符串全部满足 `下一偏移 = align_up(当前偏移 + 字节数 + 1, 4)`，没有例外。

### 5.4 分组记录

每条分组记录固定为 12 字节：

```c
struct 消息分组记录 {
    uint32_t 首字符串索引;
    uint32_t 字符串数量;
    uint32_t 分组名偏移;
};
```

分组名偏移同样相对于文件起始地址，指向 NUL 结尾 ASCII 名称。

样本闭合关系：

- 418 个分组的字符串数量总和为 7940。
- 最小首索引为 1。
- 最大 `首字符串索引 + 字符串数量` 为 7941。
- 所有分组按索引连续覆盖字符串 1 至 7940，没有重叠和空洞。

示例：

| 分组名 | 首字符串索引 | 数量 | 分组名偏移 |
|---|---:|---:|---:|
| `H1_AMESU` | 1 | 140 | `0xC46C` |
| `SH1_AMESU` | 141 | 11 | `0xC475` |
| `SETU_INFO_TANSAKU` | 7915 | 26 | `0xD982` |

### 5.5 EXE 初始化过程

`sub_570BA0` 完成以下映射：

```text
文件基址       = sub_4079A0 返回值
字符串偏移表   = 文件基址 + 0x10
分组表         = 文件基址 + *(u32 *)(文件基址 + 0x0C)
```

对应全局变量：

| 全局变量 | 含义 |
|---|---|
| `dword_177883C` | 当前消息文件基址 |
| `dword_1778844[0]` | 当前字符串偏移表基址 |
| `dword_1778848[0]` | 当前分组表基址 |
| `dword_1778424` | 内置分组 ID 到“消息文件编号、分组序号”的映射表 |

初始化函数遍历 418 个分组，将分组名交给 `sub_570B20`。若名称能映射到 EXE 内置的分组 ID，就在 `dword_1778424` 中记录当前文件编号和分组序号。

### 5.6 消息查找公式

`sub_472E90` 的一般形式支持多个消息文件。对本样本的文件编号 0，可简化为：

```text
分组 = 分组表[分组序号]
字符串索引 = 分组.首字符串索引 + 组内索引
字符串 = 文件基址 + 字符串偏移表[字符串索引]
```

若组内索引大于等于分组数量，函数返回全局空字符串。

相关函数：

- `sub_472E90`：按分组 ID 和组内索引取字符串。
- `sub_570D30`：从指定分组选择字符串。
- `sub_571070`：取得指定分组的首项。
- `sub_5699B0`：按当前消息进度读取字符串，并决定执行命令或显示文本。

### 5.7 文本命令解析

`sub_567680` 接收已经通过偏移表取得的完整 NUL 字符串，并按以下顺序解析：

1. 首字节不是 `#` 时返回普通文本类型。
2. 去掉开头的 `#`。
3. 在第一个 `:` 处分割命令名与参数文本；没有冒号时参数为空。
4. 从 EXE 地址 `0x793760` 开始线性查找命令表。
5. 命令名按字节精确比较。
6. 取得表内命令 ID，进入 `switch` 分派。

EXE 当前版本的命令表有 321 个有效项，之后以负命令 ID 结束。每项 16 字节：

```c
struct 文本命令表项 {
    uint32_t 条件过滤标志;
    const char *命令名;
    int32_t 命令ID;
    uint32_t 附加值;
};
```

命令 ID 只是 EXE 内部枚举，不出现在 DAT 文件中。DAT 中的串行格式始终是：

```text
#命令名[:参数文本]\0
```

### 6.4 A 区：参数项记录

当前样本前四条名称：

```text
なし
持ち点数
麻雀力
改造＿ツモＮＰ
```

A 区是技能参数区。记录首部是通用名称，随后最多容纳 16 个等级索引；当前样本只使用索引 `0..6`。EXE 把等级索引直接乘以 `0x848`，因此源码中的 `.level N` 使用运行时原始索引，不做 `+1` 显示换算。

#### 6.4.1 记录名称与等级地址

| 内容 | 记录内地址 | 说明 |
|---|---:|---|
| 通用名称 | `0x000`，可用空间至 `0x397` | CP932 NUL 字符串，剩余字节全零 |
| 等级块基址 `B` | `N * 0x848` | `N=0..15` |
| 等级元数据基址 `L` | `B + 0x860` | `sub_578F80` 返回的等级名称地址 |

这里的布局不是“先名称、后说明”的普通结构：六个等级文本槽位于 `B+0x398..B+0x85F`，等级名称和数值字段从 `B+0x860` 开始。最后一个等级的已定义数值区结束于 `0x8680`，与记录尾字段精确衔接。

#### 6.4.2 每级文本

| 相对 `B` 偏移 | 大小 | ASM 指令 | 运行时行为 |
|---:|---:|---|---|
| `0x398` | `0xCC` | `DESCRIPTION_1` | 第一段效果说明 |
| `0x464` | `0xCC` | `DESCRIPTION_2` | 第二段效果说明 |
| `0x530` | `0xCC` | `DESCRIPTION_3` | 第三段效果说明 |
| `0x5FC` | `0xCC` | `FORMULA_1` | 第一段带占位符公式文本 |
| `0x6C8` | `0xCC` | `FORMULA_2` | 第二段带占位符公式文本 |
| `0x794` | `0xCC` | `FORMULA_3` | 第三段带占位符公式文本 |
| `0x860` | `0x3C` | `NAME` | 等级名称；与通用名称相同时 ASM 省略 |

| 相对 `L` 偏移 | ASM 名称 | 公式占位符 |
|---:|---|---|
| `0x118` | `TSUMO` | `＃ツモ＃` |
| `0x11C` | `RIICHI` | `＃リーチ＃` |
| `0x120` | `URA_DORA` | `＃裏ドラ＃` |
| `0x124` | `DORA_YAMA` | `＃ドラ山＃` |
| `0x128` | `TENPAI` | `＃テンパイ＃` |

`sub_57A270` 的 27 个公式占位符及来源已全部恢复：`＃ＷＴ＃` 来自 `WAIT_TURNS`；上述五项来自 `SPECIAL`；`＃麻効数/麻雀Ｔ/麻雀数/麻雀Ｐ 1..3＃` 分别引用前三个普通效果槽的 `id/type/value/probability`；`＃バフＴ＃` 和 `＃デバＴ＃` 引用回合字段；`＃バフ数1..4＃` 与 `＃デバ数1..3＃` 引用相应增益/减益效果槽并经 `sub_57A5D0` 换算。

增益与减益表均采用：

```text

```

#### 6.4.4 记录尾字段

| 记录内偏移 | 类型 | ASM 指令 | 已证实行为 |

## 7. 字符串规则

- 两个样本内的日文文本均符合 CP932。
- 字符串以单字节 `0x00` 结束。
- `MBT0` 的分组名为 ASCII 子集。
- `SAM\0` 的记录字符串位于固定长度记录内部；修改字符串不能移动后续记录字段。
- `sub_567680` 和 `sub_56C9A0` 使用 `strlen`，说明运行时依赖 NUL 结束，而不是显式字符串长度。

反汇编文本按 `CLAUDE.md` 使用以下无损表示：

| 原始字节 | 汇编文本 |
|---|---|
| `5C 6E 6E` | `\n` |
| 单个 `5C` | `\\` |
| `0D` | `{{0D}}` |
| `0A` | `{{0A}}` |
| 其他不安全字节 | `{{XX}}` 或 `{{XX:XX}}` |

## 8. 反汇编文本模型

### 8.1 `MBT0`

`MBT0` 已完整结构化，采用以下最小语义模型：

```text
.format MBT0
.encoding "cp932"
.group_table_offset 0xB0D4
.string_slot_count 7941

.group "H1_AMESU"
TEXT "..."
.endgroup
```

字符串尾部填充可由长度唯一推导，因此汇编文本不输出 `.zero`。汇编器会在 NUL 后自动补齐至 4 字节边界。分组首索引、分组数量、分组名偏移和字符串偏移也全部重新计算，不在文本中重复记录。

### 8.2 `SAM\0`

`SAM\0` 已按技能、礼装/装备、角色/战斗配置三个用途区语义化。源码只记录不能从结构和字段值推导的信息：

```text
.format SAM
.encoding "cp932"

.section SKILLS
.record
NAME "プリンセスストライク"
.level 6
NAME "プリンセスヴァリアント"
DESCRIPTION_1 "自分の物攻アップ中＆物防アップ特大＆魔防アップ特大"
SPECIAL RIICHI 100
SPECIAL URA_DORA 200
SPECIAL DORA_YAMA 4
BUFF category=1 turns=6
BUFF_EFFECT slot=0 id=211 rank=2
.endlevel
UI_ICON_ID 16
PROFILE_ID 1
UNLOCK_LEVEL 6
.endrecord
.endsection
```

三个区段名称为 `SKILLS`、`ITEMS`、`PROFILES`。每条 `.record` 的固定大小由区段定义决定，不写入源码；A 区的 `.level N` 使用 EXE 直接索引的 `0..15` 等级号。

最小化规则如下：

- 空字符串和零数值字段不输出，由全零记录缓冲自动恢复。
- 等级 `NAME` 与记录 `NAME` 相同时不输出，汇编器自动复制记录名称。
- `EFFECT`、`BUFF_EFFECT`、`DEBUFF_EFFECT` 保留原始 `slot`，避免前置空槽改变运行时索引。
- 区段记录数、记录大小、文件偏移和区段间对齐均可推导，不写入源码。
- 固定字符串槽的 NUL 和尾部零、保留零区及记录未使用区域均自动生成，不输出 `.zero`。
- 不使用 Base64、十六进制转储、`.byte` 或其他原始数据块。
- 反汇编器为所有已定义字段标记字节范围，并扫描整条记录；语义模型之外只要出现一个非零字节，就以“记录索引 + 记录内偏移”报错，禁止静默丢失。

## 9. 零突变重建要求

### 9.1 `MBT0`

汇编器必须：

1. 保留字符串索引 0 的零偏移。
2. 按分组顺序连续分配字符串索引。
3. 重新计算所有分组名和消息字符串偏移。
4. 在有效偏移表末尾至分组表之间补零。
5. 为每个名称和消息写入且只写入一个 NUL。
6. 根据字符串编码后的字节长度，在 NUL 后自动补零至 4 字节边界。

### 9.2 `SAM\0`

汇编器必须：

1. 为每条记录按所属区段的固定大小创建全零缓冲，再把源码中的语义字段写入固定偏移。
2. 自动写入固定字符串的单个 NUL 和槽尾零；省略的等级名称从记录名称恢复。
3. 校验字符串槽容量、等级/数组/效果槽索引、整数宽度、字段重复定义和区段闭合关系。
4. 按源码中的记录数自动生成三个区段计数；记录大小固定为 `0x884C`、`0x1E4`、`0x510`，不接受源码覆盖。
5. 固定从 `0x28` 写入 A 区，并将 B、C 区起点自动向上对齐到 16 字节；头部保留区和区段间隙由全零输出缓冲恢复。
6. 自动计算并写入 A、B、C 区偏移，最终文件在 C 区末尾结束。
7. 拒绝未知指令、未知区段、非法符号值和任何不能无歧义重建的输入。

## 12. 工具使用与验证

实现文件：

- `opcodelist.py`：格式常量、文本命令映射和无损字节转义。
- `disassembler.py`：识别 `MBT0`/`SAM\0`，生成 UTF-8 汇编文本。
- `assembler.py`：读取汇编文本，重建原始 DAT 字节。

单文件反汇编：

```powershell
python disassembler.py MC_ADD_unpacked\DID_MES_00_DAT
python disassembler.py MC_ADD_unpacked\DID_PURI_PARA_DAT
```

默认分别生成：

```text
MC_ADD_unpacked\DID_MES_00_DAT.asm.txt
MC_ADD_unpacked\DID_PURI_PARA_DAT.asm.txt
```

重建：

```powershell
python assembler.py MC_ADD_unpacked\DID_MES_00_DAT.asm.txt
python assembler.py MC_ADD_unpacked\DID_PURI_PARA_DAT.asm.txt
```

默认输出文件名为原资源名加 `.rebuild`。文件或目录参数均可一次传入多个；目录模式递归批处理。`-o` 仅用于单输入文件，`--encoding` 可覆盖默认或汇编头部的 CP932。
